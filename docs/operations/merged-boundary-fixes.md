# 四批合并后的边界修复

日期：2026-10-24。修复基线：`edbe4b0`。仅修改源码与测试，未安装本机固定运行包、未迁移真实知识库。

## 修复范围

1. **探针数据隔离**：`executor probe --isolation` 使用独立子进程、临时配置、临时知识库及临时工作目录。禁止探针库自动拉取/推送、Embedding、value事件和team统计；父进程不切换共享配置，不向当前库写合成作业/卡片。子进程固定使用调用方同一源码/构建，超时清理进程树，退出后清理临时目录。该数据隔离不替代宿主自己的工具权限或操作系统沙箱；真实执行器仍须单独验收。
2. **v2身份保真**：白名单保留成员绑定、宿主、会话、任务及版本等标量上下文；导入到聚合库对应列。最小包继续排除查询、正文、原始工具结果和凭据。正式 `knowledge.delivered → knowledge.used → task.completed` 通过打包/导入后仍能按相同身份核对。
3. **递送关联隔离**：采用匹配必须同时指定host_profile、session_id、context_event_id、memory_id及content_revision；不同宿主/会话复用同一事件ID时不会串联。
4. **接回原team周期链**：统一worker新增team_sync任务，复用原service.run完成采集、Git同步、看板/README更新。team未启用则跳过；启用后使用原身份、历史和ACK，不重新enroll。替换旧定时入口不再丢失该任务。
5. **真实结果与持久退避**：handler返回的error/errors/warning（含嵌套发送失败）按失败记账；blocked/skipped分别记录，不推进成功水位。失败次数跨tick持久保存，成功后归零；CLI `worker once` 在失败或丢失租约时返回非零。
6. **租约与接管**：后台心跳续租；每项任务前和结果入账时核对owner、fencing及有效期。失去租约的旧实例停止后续任务和结果入账，不能清除后续实例的租约。正在进行的外部调用仍受原超时约束；心跳不绕过各子系统已有的锁/同步租约。
