# Hook 降噪交付（2026-10-23）

针对 [ZCode会话核查](reviews/zcode-noise-audit-2026-10-23.md) 的两次Stop续跑问题，调整所有宿主共用的Hook内核及MCP初始化说明。

## 当前行为

- **Stop始终静默结束**：没有decision=block，没有普通提炼催办，也不要求补存或未采纳阅读的反馈。材料解析/采集失败保留内部状态，诊断写stderr，正常退出不把故障转为模型新任务。新旧inflight入口一致。
- **自动采集仍运行**：执行中、Stop、压缩前按原检查点保留观察与合格增量，队列/作业接口可查询。普通待办不再通过SessionStart、UserPromptSubmit或工具Hook要求立即claim/material/submit。没有新增后台LLM或自动创建聊天；明确整理知识/维护任务仍可用原协议。
- **提示有预算**：同一宿主会话内，每个不同用户输入最多2条自动提示，每条上限900字符；重复计划/相同提示不重复注入，新输入重置。超长提示不截断身份或证据后发送；显式memory_context/read/feedback不受此自动提示预算限制。
- **启动规则缩短**：1263→535字符，保留具体topics示例、实际采纳、版本及真实任务反馈、业务规则出处。初始化MCP说明及capture返回语也移除了“阶段结束后必须继续提炼”的相反要求。
- **过滤确定性噪音**：只作用于Hook自动入队，跳过宿主system/reminder、工具前置信封、常见运维文档回显、明显一次性产品评估/状态报告。带明确业务规则或标准知识结构的内容保留；业务文档和用户纠正不按“文档/长文本”一刀切过滤。原始观察仍保留，记录过滤原因计数并推进采集游标；明确调用memory_capture收集观察时，可重访被自动过滤的材料，已入队文本仍去重。
- **主动提交不变**：用户明确调用memory_capture提供材料、文档import、memory_save/update及反馈演进保持原契约。过滤是保守规则，不承诺识别所有无价值材料，也不把队列入库当成卡片保存。

## 配置与生效

新增 `inflight.hook_notice_budget`（默认2，允许下调为0）和 `hook_notice_chars`（默认900，可下调）；代码硬上限分别2/900。禁用hooks时自动提示和Hook观察均不继续执行。

三宿主仍指向唯一 `~/.knowbase/runtime/venv/bin/python`，原地安装，不增加版本目录。Hook逐次启动进程，安装后Stop行为即时采用新逻辑；旧MCP连接保留先前初始化说明，需要重连knowbase或新会话加载一致的新说明。没有终止现有聊天或批量关闭旧作业。

如果Trae等宿主曾手工复制旧全局规则，应删除其中“阶段结束后立即claim/续页/逐段结算”的要求，以当前规则为准；新MCP初始化说明已明确普通维护不占用主任务。此次不通过原生UI强改用户全局规则。
