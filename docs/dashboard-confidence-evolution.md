# 卡片统计与反馈驱动演进

## 用户结果与数据契约
首屏能判断调用、知识状态、命中、更新和 Token 情况。调用来自 command_calls，旧 usage_log 独立注明，不相加；更新调用不冒充成功修改次数。状态是当前库存，运行统计是累计观测。命中按有可用命中明细的检索计算，旧缺失明细单列。Token 优先使用 model.usage；没有入账事件时可只读本机 Claude 用量来源，标注来源和覆盖范围。没有配对对照不计算净节省；缓存读取另列，不直接归因于 knowbase。

## Hermes 参考及取舍
参考官方 https://hermes-agent.nousresearch.com/docs/user-guide/features/memory 和 /skills：任务后复盘、按需读取、持久化可复用经验。Hermes 的后台复盘可额外消耗模型 Token，且支持预算、开关和待审；其机制不等同于统计置信度。

本期复用现有 Hook/宿主模型/提炼队列与反馈事务，不引入后台付费模型。反馈触发确定性的置信度判定，形成提炼→验证→回填→升降级→再次检索闭环。

## 自动演进契约（含业务规则，用户明确授权）
- 默认阈值：当前版本至少 3 个独立已完成任务、至少 2 个会话的 helpful；同一个工具也可以累积独立证据。2 个独立任务 not_helpful 自动失效；incorrect/outdated 沿既有版本反馈规则立即失效。
- 按 memory_id+content_revision 收集版本绑定反馈；重复 task_key 只能贡献一份证据，同任务正负冲突阻止晋升。
- 业务规则候选通过同 scope 的任务关联阅读取得验证回执，反馈须显式 task_result=completed，不能把普通阅读计为验证成功。
- 候选业务规则达到独立任务及会话阈值、来源有效且无冲突时自动激活；标准/全局偏好不自动激活。
- 负面有效反馈使 active/staging 内容 stale，退出默认检索；保留历史，不物理删除。失效内容需修订形成新版本后重新验证。
- 新版本不能继承旧有效性。服务在 RepoLock 内写前记录回执、原子落盘、读回并更新索引；自动激活的移动在同一恢复流程完成。
- 配置可关闭自动晋升或业务规则激活；关闭不删除证据。旧人工 promote/verify 入口继续存在。

## 验收与交付
统计测试覆盖缺表/未知、调用口径、命中和 Token；演进测试覆盖独立性、失败、冲突、重放、版本更新、业务规则自动激活/淘汰及故障恢复。设计稿和实际输出可在本地打开，主页面不含原始搜索历史。真实宿主新协议需升级后生效，不能把源码回归当作已部署。
