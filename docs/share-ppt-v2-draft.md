## 逐页文案

### P1 封面
- 主标题：薪火 knowbase
- 副标题：给 AI 装上"部门集体记忆"
- 一句话：AI 帮你干活时踩过的坑、学会的招，自动记下来、全部门共享——下一个遇到同样问题的人，一问就有答案。
- 标签：数据不出内网 / 所有 AI 工具共用 / 全程有记录可回溯

### P2 是干什么的
- 标题：薪火 knowbase 是干什么的？
- 三卡：
  1. **同一个坑，不再踩第二遍**——AI 排查两小时才解决的问题，自动记成一条经验；下次任何人遇到同样问题，AI 直接给答案，不用重来。
  2. **换个工具，经验还在**——你在 Claude Code 里踩的坑，ZCode、Trae 都能查到：所有 AI 共用一本记忆。
  3. **老经验不再"人走茶凉"**——排查诀窍、团队规矩，从"口口相传"变成"随时可查"。
- 底部大字：把踩过的坑，从**个人的、一次性的**，变成**部门的、永久的**。

### P3 怎么干的
- 标题：怎么做到的？——一条经验的旅程
- 五步流程：
  1. AI 干活：踩坑、排查、解决
  2. 自动写成一张"经验卡"：现象是什么 / 为什么 / 怎么办——三段齐全才收
  3. 存进部门经验库：每张卡带作者和时间，改动全程有记录
  4. 下次有人问到相关问题，经验自动递到 AI 眼前（不用记得去搜）
  5. 用过的人反馈"有用 / 没用"——经验随之升级或淘汰
- 类比条：像老司机带路：走过一次的路自动画进地图，后来的人照着走就行。

### P4 为什么有效①：怎么找到的（三路搜索的"怎么做"）
- 标题：怎么找到的？——三路搜索各干各的活
- 引导：拿真实例子走一遍——搜"测试总是随机挂"，目标《CI 上测试随机失败的排查记录》
- 三卡（每卡"怎么做 + 例子里"）：
  1. **路① 索引对照表（主路）**——每张卡入库时切成"三字碎片"（"随机失败"→随机/机失/失败），攒成"碎片→出现在哪些卡"的对照表，像书的索引页；搜索时把问题同样切碎去翻表，共同碎片越多越靠前。例子里："总是""随机"碎片目标卡都有→秒对上；写错一个字其余碎片照样命中。
  2. **路② 逐字查找（兜底）**——像 Ctrl+F，词作为连续文字出现在卡里就算对上。例子里："CI"这种两字母短词切不出三字碎片，由它补上。
  3. **路③ 指纹比对（意思相近）**——给每张卡算一幅"词汇指纹"（所有词晕染成的数字画像），问题也算一幅，画像越像分越高。例子里：中文问题 vs 英文标题 flaky test，靠卡内"测试/失败/随机"相关词画像接近被捞上。小字：现指纹是"字面画像"，真语义理解在下一站。
- 底部融合条：三路结果不比分数比名次——像三位评委各排各的名次再综合，三路都靠前的胜出。

### P5 为什么有效②：找到后怎么排座次
- 三卡：① 先给本项目的答案（A 项目优先，20/20 全对）② 靠谱的排前面（有用加分、过时沉底）③ 垃圾进不了场（退休/待审/矛盾的，排座次前就被请出去）
- 底部：上一页例子跑通——中文问题、英文标题，照样秒中

### P6 怎么存进去的：存哪些、怎么存
- 标题：怎么存进去的？——不是什么都收，收了就规规矩矩
- 引导（例子续）：AI 花两小时解决了"支付网关验签失败"（根因：时间戳要用毫秒）——哪些能进库？怎么进的？
- 左卡【存哪些——先过"值不值得"关】：
  - 收：下次还会踩的坑、排查结论、团队规矩
  - 不收：干完就完的一次性修复记录（过程进代码提交历史）、"208/208 通过"类过程数字、代码库里本来就能查到的事实
  - 例子里：《两小时排查过程记录》不收；"网关验签时间戳必须毫秒"这条结论收
- 右卡【怎么存——五道门】：① 值不值得 ② 格式齐不齐（现象/原因/正确做法三段，缺一段打回；密码密钥拦下）③ 是不是流水账（"阶段收尾实测""全部通过"字眼劝退去日报）④ 是不是重复（与已有卡高度相似拒收，"去补充那张卡"——例子里：补充根因而非另开新卡）⑤ 规矩类必须人审（进待审区，人点头才生效）
- 底条【存的过程】：编号 → 写卡 → 存档（自动记录谁写的、何时）→ 更新索引，一气呵成不会出现半张卡；新卡一律从"待验证"起步——刚写的不算真理，用过才算

### P7 经验怎么更新：接棒，而不是覆盖
- 引导（例子续）：网关升级了，《验签时间戳用毫秒》过时了——老经验怎么处理？
- 三卡：① 缺了就补原卡（直接改那张卡，全程有记录）② 过时就接棒（新经验接棒，旧卡自动标"已过时"但不删除，可退回）③ 矛盾不裁判（只贴"互相矛盾"标记靠边站，由人裁决，绝不自动选边）
- 底卡【防污染三条铁律】：① 改内容不能自己给自己发"已验证"标签 ② 正式规矩 AI 改不了只能人改 ③ 每次修改都留历史版本随时退回
- 【淘汰路径】：反馈"不管用了" → 全员立刻看到"已过时" → 确认后归档退休，永远不再出现
- 原"快"的数据（眨眼 100 毫秒 vs 2.3 毫秒）并入 P12 成果页

### P8 用了什么技术
- 标题：里面用了什么？——四样"家常菜"
- 四卡：
  1. **经验卡 = Markdown 文本**——双击就能打开看，人读得懂，不是黑盒
  2. **版本记录 = git**——每次修改都留历史，改坏了随时退回去：文档的"后悔药"
  3. **快速索引 = SQLite**——一个文件就是个小数据库，不用安装任何数据库软件
  4. **通用插座 = MCP**——AI 助手行业的通用接口标准，各家 AI 都能直接插
- 底部：全部跑在自己电脑 / 内网里，不依赖任何外部服务，数据不出门。

### P9 为什么选这些技术
- 标题：为什么选这几样？——四个"没选 XX"的原因
- 四行（问题 → 我们的选择 → 为什么）：
  1. 记忆放哪？→ 放本地，不用云端记忆服务 —— 经验含公司系统信息，**数据不能出内网**
  2. 要不要上 AI 平台？→ 不上，一个轻量服务就够 —— 平台要专门团队运维；我们要"装完就能用，拷走就能搬"
  3. 小数据库够用吗？→ SQLite 刚刚好 —— 几万条以内毫秒级；坏了 0.24 秒全量重建
  4. 各家 AI 怎么接？→ 走 MCP 标准 —— 不为每个 AI 单独开发，贴段配置就能接入
- 底部金句：选型标准只有一条：**内网能跑、零运维、坏了能重建。**

### P10 谁在管：AI 与人的分工
- 标题：放心用的关键——AI 能做什么、不能做什么
- 左卡（AI 可以）：记经验 / 查经验 / 反馈"有用没用" / 对规范提建议
- 右卡（AI 不可以）：改公司规范（建议进"待审区"，人批准才生效）/ 给自己发"已验证"标签 / 把数据发到库以外
- 底部：**AI 贡献事实，人守规矩门。** 每条经验带作者和时间，改过什么全程可查、可回滚。

### P11 日常怎么操作
- 标题：AI 六个动作，人四把钥匙
- 左侧 AI 动作表（时机 / 动作 / 白话）：
  - 开工 memory_search 把相关经验递上来
  - 命中 memory_read 读经验全文
  - 干完 memory_save 写新经验卡
  - 补充 memory_update 修正已有经验
  - 用完 memory_feedback 说"有用/没用/过时"
  - 汇报 memory_stats 库里有什么、用了多少
- 右侧人的钥匙：verify 盖章"这条有效" · promote 批准新规范 · revise 修改正式规矩 · archive 让旧经验退休；外加 doctor 体检、dashboard 管理看板
- 底部：AI 的每个动作都有记录，人保留最终决定权。

### P12 已经跑起来了
- 四大数字：3 个 AI 工具在用 / 41 条有效经验（另 10 条已退休）/ 65 次修改全程可查 / 93 项自动测试护航
- 效果条：检索命中从一半提升到六分之五；同类问题排查从小时级到分钟级；搜索快到无感（眨眼 100 毫秒，它 2.3 毫秒搜完）
- 底部：预估 2 人周的工程，AI 主导 1 个工作日建成——这本身就是最好的示范。

### P13 五分钟加入
- 四步：拿代码 → 一条命令安装初始化 → 把配置贴进你的 AI 工具（README 可抄）→ 继承全部部门经验
- 安全承诺：纯内网 / 推送白名单（配错外网直接拒绝）/ 全程可回滚

### P14 结尾
- 大字：一个人的坑，所有 AI 的经验。
- 三件事：现在就接入（5 分钟）/ 现场出题当场入库 / 把你手头的"口口相传"变成可查的资产
- 路线图：更聪明的语义搜索 · 多人多地同时写 · 定期把高频经验编入部门知识库
