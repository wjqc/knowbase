怎么找到的？——三路搜索各干各的活

拿一个真实例子走一遍：你搜"测试总是随机挂"，库里躺着一张《CI 上测试随机失败的排查记录》——它是怎么被找到的？

路① 索引对照表（主路）

怎么做：每张卡入库时切成"三字碎片"（"随机失败"→"随机 / 机失 / 失败"），攒成一张对照表：碎片 → 出现在哪些卡，就像书的索引页。搜索时把你的问题同样切碎去翻表，共同碎片越多越靠前。

例子里：问题切出的"总是""随机"等碎片，目标卡里都有 → 秒对上。就算写错一个字（"随几失败"），"失败"等其余碎片照样命中。

路② 逐字查找（兜底）

怎么做：像在文档里按 Ctrl+F——只要你的词作为一串连续文字出现在卡里就算对上。

例子里：像"CI"这种两个字母的短词，切不出三字碎片，主路使不上劲——由它补上。

路③ 指纹比对（意思相近）

怎么做：给每张卡算一幅"词汇指纹"（卡里所有词晕染成的数字画像），你的问题也算一幅，两幅画像越像分越高——字面完全不同也能对上。

例子里：卡标题是英文"flaky test"，但卡里满是"测试 / 失败 / 随机"相关词，画像和你的问题接近 → 捞了上来。

现在的指纹是"字面画像"，还不是一个字不差就能懂含义——真·语义理解排在下一站

三路结果怎么合？不比分数，比名次——像三位评委各自排名再综合，三路都靠前的卡胜出，然后进入下一页的排座次

找到了一堆候选，怎么排座次？

① 先给本项目的答案

在 A 项目里问，A 项目的经验排最前，全部门通用的随后——绝不拿 B 项目的答案糊弄你（20 次测试 20 次全对）。

② 靠谱的排前面

被多人用过、说"有用"的加分靠前；没人验证过的原样待着；被反馈"过时"的沉底。

③ 垃圾进不了场

已退休的、待人审核的、互相矛盾的——在排座次之前就被请出去，不会拿旧答案误导你。

上一页的例子跑通："测试总是随机挂" →《CI 上测试随机失败的排查记录》——中文问题，英文标题，照样秒中

怎么存进去的？——不是什么都收，收了就规规矩矩

接着走例子：AI 花两小时解决了"支付网关验签失败"（根因：时间戳要用毫秒）——哪些能进库？怎么进的？

存哪些——先过"值不值得"关

  • 收：下次还会踩的坑、排查结论、团队规矩
  • 不收：干完就完的一次性修复记录（过程进代码提交历史）；"208/208 通过"这类过程数字；代码库里本来就能查到的事实

例子里：《两小时排查过程记录》不收；"网关验签时间戳必须毫秒"这条结论收

怎么存——五道门，道道有人守

  • 门① 值不值得：见左
  • 门② 格式齐不齐：必须写清"现象 / 原因 / 正确做法"三段，缺一段打回；卡里出现密码密钥直接拦下
  • 门③ 是不是流水账：写着"阶段收尾实测""全部通过"这类字眼 → 劝退，请去日报
  • 门④ 是不是重复：与库里已有的卡高度相似 → 拒收："去补充那张卡，别再存一张"——例子里：已有《支付网关签名报错》，这次是补充根因而非另开新卡
  • 门⑤ 规矩类必须人审：团队规范、业务规则只能进"待审区"，人点头才生效

存的过程一气呵成：编号 → 写卡 → 存档（自动记录谁写的、何时）→ 更新索引，不会出现半张卡； 新卡一律从"待验证"起步——刚写的不算真理，用过才算

经验怎么更新？——接棒，而不是覆盖

例子继续：网关升级了，《验签时间戳用毫秒》过时了——库里的老经验怎么处理？

缺了就补原卡

发现已有经验不完整，直接改那张卡（例：补充"沙箱环境豁免"）——谁改的、改了什么，全程有记录。

过时就接棒

新经验《升级后改用秒 + 签名版本号》接棒时，旧卡自动标"已过时"但不删除——历史都在，接错了随时退回。

矛盾不裁判

两条经验打架？系统只给双方贴"互相矛盾"标记、排座次时靠边站——由人裁决，绝不自动选边。

防污染三条铁律：① 改内容不能自己给自己发"已验证"标签——可信度只由真实使用说了算　② 正式规矩 AI 改不了，只能人改　③ 每次修改都留历史版本，随时退回任何一版
淘汰路径：有人反馈"不管用了" → 全员立刻看到"已过时" → 确认后归档退休，永远不再出现

放心用的关键：AI 能做什么、不能做什么

AI 可以

  • 记经验（踩过的坑、排查结论）
  • 查经验（干活前自动带上相关经验）
  • 反馈"有用 / 没用"

AI 不可以

  • 改公司规范——建议只能进"待审区"，人批准才生效
  • 给自己发"已验证"标签——可信度只由真实使用说了算
  • 把数据发到库以外的地方

AI 贡献事实，人守规矩门。每条经验带作者和时间，改过什么全程可查、可回滚
