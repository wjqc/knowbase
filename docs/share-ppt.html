解决的问题 · 01

AI 用得越深，经验浪费得越狠：三层浪费

会话内

会话结束，踩坑过程、试错结论随上下文全部销毁—— 为了一个配置反复试错一下午，结论只活了两小时。

工具内

Claude Code、ZCode、Trae 各有各的记忆，但互不相通—— 在这个工具里踩过的坑，换个工具原样再踩。

人际间

老员工的排查经验靠口口相传，无结构化载体—— 不能沉淀、不能审计、不能复用。

真实代价举例：内网 VPN 客户端在 macOS 上启动即死锁—— 反复重启重登、多轮搜索无果；正确答案（升级版本 + 一条验证命令）其实一行字就能说清。 这样的坑，每个人、每个工具都在重复踩。

解决的方案 · 02

定位：不是"又一个记忆功能"，是可治理的经验基础设施

现成方案短板（我们的场景）薪火的做法
Mem0 / Zep 等云端记忆数据出内网，一票否决纯本地：markdown + git + SQLite
Letta / MemOS 等平台平台级部署，绑框架，运维重MCP 协议，任何 Agent 零侵入接入
单工具内置记忆经验锁死在单个工具里一个库喂所有 Agent（核心差异）
通用开源记忆方案无人员标准治理、无部门联动标准仅人改 + 与部门知识库分层联动
Agent 可以贡献事实性经验，但不能自行定义组织规范——
证据由 Agent 提交，状态由服务端裁决。

架构：三条不变量撑起的经验流水线

收集层

会话开场注入规则

6 个工具
search / read / save

存储层

markdown 人可读可审计（git）
SQLite 全文索引（可重建）
标准/偏好 staging 人审

① 唯一真相

Markdown 是唯一真相，Git 是唯一审计；索引坏了 reindex 一键重建。

② 写路径单行化

多 Agent 并发写全部过 repo 级跨进程锁，分配编号→落盘→提交→重建索引一气呵成。

③ 状态机裁决

经验等级 once → verified → stale 由服务端按使用反馈计算，Agent 无法自封"已验证"。

日常怎么用：Agent 的六步习惯，人的三件治理

时机Agent 动作

人的治理（CLI）

  • verify 确认经验有效
  • promote 审批 staging 提案
  • stats 看沉淀与命中漏斗

自动闭环（hooks）

  • 任务前：自动检索不经模型自觉
  • 任务后：漏存会被追问一次

应用场景 · 05

场景① 排障避坑：一次踩坑，全员免疫

过去：VPN 客户端 macOS 死锁

  • 反复重启、重登，多轮搜索无果
  • 结论散落在某个人的脑子里
  • 下一个遇到的人（或 Agent）原样再来一遍

现在：一条经验，跨工具生效

  • 现象 / 原因 / 正确做法 / 验证命令结构化入库
  • Claude Code 存一条 → ZCode、Trae 检索即中
  • 客户端升级导致失效？一条 feedback 全员标记过时

同类已入库实战

Docker 拉镜像直连超时 → 镜像加速；多仓库项目根目录 git 报错 → 子仓库纪律；HAR 分析 304 压缩误判 → 只看 200 响应。

任务前自动检索

你说"内网连不上"，钩子自动把 VPN 那条经验注入上下文——不需要你想起去搜索。

经验会进化

客户端升级后经验过时？一条 outdated 反馈，全员立刻看到"已过时"标记，不再被旧答案误导。

应用场景 · 06

场景② 标准沉淀：规范长在工具里，而不是文件夹里

真实案例已在发生：S-2026-0001 AI 编程工具接入规范

工具矩阵、两级验收、统一指针块，路由/可观测/发布门禁/测试/文档五类标准摘要—— 由 AI 会话按规范自动写入标准库，多次修订全程 git 审计； Agent 写标准只能进 staging/ 提案区，人工审过才生效—— AI 贡献事实，人守规范门。

对管理者

规范发下去不再"石沉大海"：Agent 干活前自动带上最新标准，违规写法在生成时就被纠正。

对执行者

不用背规范文档：写代码时标准就在上下文里；标准改了，下一次会话自动生效。

对审计

每条记忆带来源（哪个工具、哪个会话）、时间线、修订历史——经验可追溯、可回滚。

应用场景 · 07

场景③ 多项目规模化：项目越多，越要"先问对库"

压力测试：20 项目 × 340 条记忆

单次检索耗时（毫秒级，千条无压力）

实测 1.1 ms / 次

带项目标签（scope）检索精准率

20 个项目逐一验证：20 / 20 全部命中本项目

项目目录自动感知：在哪个项目里干活，就优先查哪个项目的经验；跨项目通用经验始终可见。

为什么不会"越攒越乱"

  • 写入必过 lint：结构、必填小节、密钥拦截
  • 标题查重：相似经验提示合并而非重复入库
  • 生命周期：单次经验 → 多次验证 → 过时淘汰
  • 季度人工"蒸馏"：高频验证经验升格进部门知识库

信息熵防护栏：热记忆层（机器高频写）与冷知识层（人工策展）严格分层。
